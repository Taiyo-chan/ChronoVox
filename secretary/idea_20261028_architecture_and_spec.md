# 技術スタックとディレクトリ・AIパイプライン設計

## 1. 決定した技術スタック
- **ターゲット端末**: iPhone 12（iOS 16+ / iOS 17+ 想定）
- **フレームワーク・言語**: Swift / SwiftUI
- **オーディオ処理**: `AVFoundation`（`AVAudioSession`, `AVAudioRecorder`, `AVAudioPlayer`）
  - バックグラウンド録音対応（画面ロック中や他アプリ操作中も録音継続）
  - リアルタイム音量レベル取得による波形アニメーション表示
- **ストレージ・ファイル連携**:
  - アプリ内 `Documents` ディレクトリを iOS 標準の「ファイル（Files）」アプリおよび iCloud Drive / Mac 共有に対応（`UIFileSharingEnabled` / `LSSupportsOpeningDocumentsInPlace`）。
  - アプリ内UIでのプロジェクト作成・編集と、「ファイル」アプリ経由でMac等から直接Markdownファイル等を配置する運用の**両方**に対応。
- **AI基盤**: **Gemini API**（マルチモーダル音声入力対応モデル）
  - 音声ファイル（`.m4a`）を直接入力し、以下の3モードを実行可能：
    1. **通常書き起こし**
    2. **人物ごとの書き起こし（話者分離）**
    3. **プロジェクト文脈（概要・進捗・過去ログ）を踏まえた議事録生成**

---

## 2. 画面構成とユーザーフロー設計

### ① 録音画面（メイン画面）
- **大型タイマー表示**: ストップウォッチのように経過時間（`00:00.00` または `00:00:00`）を大きく中央に表示。
- **リアルタイム波形**: 音声入力レベルに応じた波形表示。
- **標準ボイスメモ機能**:
  - 赤い録音ボタンで録音開始
  - 一時停止（Pause） / 再開（Resume）
  - 録音完了（1ファイル確定）
- **連続録音セッション**:
  - 1つの音声ファイルを録音終了しても、セッションを維持したまま即座に次の録音を開始可能。
  - 現在のセッションで録りためた音声ファイル一覧（テイク一覧）が画面下部またはドロワーに表示され、まとめて振り分けに進める。

### ② セッション終了後のトリアージ（振り分け）画面
一連の録音が終わったら、録音した各音声ファイルに対して：
- **プレビュー再生 / シーク / トリミング**
- **削除**: 不要なファイルをその場で削除
- **プロジェクトディレクトリへの格納**:
  - 既存のプロジェクトフォルダを選択、または**その場で新規プロジェクトフォルダを作成**して移動・保存。

### ③ プロジェクト詳細＆AI処理画面
プロジェクトディレクトリを開くと、以下のタブ・機能を利用可能：
1. **コンテキスト管理（概要・進捗）**
   - プロジェクトの概要（`overview.md`）と進捗状況（`current_status.md`）をアプリ内で閲覧・編集（またはファイルアプリ経由で配置）。
2. **音声ファイル一覧＆AIアクション**
   - 格納された各音声ファイル（または複数選択）に対してボタン1つで実行：
     - 📝 **書き起こし**
     - 👥 **人物ごとに書き起こし（話者分離）**
     - 📋 **議事録（要約）を作る（過去文脈参照）**
3. **過去の議事録・書き起こし履歴**
   - 生成された議事録や過去の書き起こしを時系列で閲覧・編集・共有。

## 3. プロジェクトディレクトリのフォルダ構造案

「ファイル」アプリから見ても分かりやすく、Mac上のプロジェクト管理（`PM/` フォルダ等）とも親和性が高いMarkdownベースの構造を採用します。

```text
Projects/
  └── <プロジェクト名>/
        ├── overview.md         # プロジェクトの概要・目的・参加者情報など
        ├── current_status.md   # 現在の進捗状況・直近の課題
        ├── audio/              # 格納された音声ファイル (.m4a)
        ├── transcripts/        # 書き起こし・人物別書き起こし (.md)
        └── minutes/            # 過去の議事録 (.md)
```

### 文脈付き議事録生成の仕組み
「議事録を作る」を実行した際、アプリは自動的に同じプロジェクトフォルダ内の：
1. `overview.md`（プロジェクト概要・登場人物の前提知識）
2. `current_status.md`（現在の進捗状況）
3. `minutes/` 内の直近の過去議事録（および必要に応じて過去の音声/書き起こし）
を読み込み、今回の音声データとともに Gemini API へ渡します。
これにより、**「前回の会議からの進捗」「文脈に即した専門用語や人物の特定」「今回の決定事項とネクストアクション」**を盛り込んだ質の高い議事録を生成します。
